# Общие папки и предложения через PR

Владелец выдаёт ссылку на проект (`/`) или существующую папку. Режимы: `READ` — чтение и скачивание без входа; `PROPOSE` — дополнительно предложения после входа через существующую DocGrid SSO. Общая ссылка не делает получателя участником проекта и не разрешает прямые изменения. В БД хранится SHA-256 токена из 32 случайных байтов. Срок: до года; отзыв немедленно блокирует новые запросы, включая скачивание и отправку/принятие PR. Уже скачанные копии отзыв не удаляет.

Доступ распространяется на исходники и основной вариант рабочих документов в выбранной папке и её потомках. Проверяется граница сегмента (`/Case` не включает `/Case2`). Корзина, другие ветки, обсуждения, LLM-доступы и документы вне папки не публикуются. Предложенные файлы не появляются в публичном списке до принятия. Автор видит только свои PR; владелец и участник `REVIEWER` рассматривают PR проекта.

## Маршруты

Префикс: `/api/docgrid`.

| Метод и маршрут | Назначение | Авторизация |
| --- | --- | --- |
| POST `repositories/:project/shares` | `{path, mode, expiresAt}` → ссылка, токен только при создании | Владелец |
| GET `repositories/:project/shares` | Список без токенов | Владелец |
| POST `repositories/:project/shares/:id/revoke` | Отзыв | Владелец |
| GET `shared/:token` | Область, папки и файлы с `baseHash` | Общая ссылка |
| GET `shared/:token/files/:kind/:id/content` | DOCX/Excel для просмотра | Общая ссылка |
| GET `shared/:token/files/:kind/:id/download` | Файл или рабочий DOCX | Общая ссылка |
| POST `shared/:token/proposals` | MOVE или EDIT | SSO + ссылка PROPOSE |
| POST `shared/:token/uploads` | multipart: `file`, `path`, `body` | SSO + ссылка PROPOSE |
| GET `shared/:token/proposals` | Собственные PR | SSO + действующая ссылка |
| GET `repositories/:project/shared-proposals` | PR с содержимым до/после и изменениями ячеек | Владелец / REVIEWER |
| GET `repositories/:project/shared-proposals/:id/download` | Предложенный файл до решения | Владелец / REVIEWER |
| POST `repositories/:project/shared-proposals/:id/decide` | `{action: MERGE или CLOSE}` | Владелец / REVIEWER |

MOVE: `{kind, fileKind: material|document, id, baseHash, path, title, body}`. EDIT использует `content` для DOCX/рабочего документа либо `cells: [{sheet, row, column, value}]` для XLS/XLSX (индексы от нуля). Формулы вводятся с `=`. Не более 1 000 ячеек на PR. PDF, изображения и другие исходники можно добавлять и перемещать; их содержимое не редактируется.

При принятии MOVE меняется только папка. Правка рабочего документа создаёт коммит и новую редакцию основного варианта. Правка загруженного DOCX/Excel создаёт отдельный файл «… — редакция <PR>.docx/xlsx»; исходник и его SHA-256 сохраняются. Все решения, создания и отзывы ссылок фиксируются в журнале. Принятие транзакционное, под блокировкой проекта. Несовпадение исходной папки, контрольной суммы или рабочей редакции даёт 409; требуется новый PR. Повторно принять один PR нельзя. Автоматического слияния конфликтующих правок нет.

## Ограничения и развёртывание

- Сначала развернуть бэк с миграцией `20261008100000_shared_folders`, затем фронт. Новые переменные окружения не нужны.
- Загрузки и предложенные редакции ограничены 32 МБ; открытые PR учитываются в общем лимите проекта 500 МБ вместе с исходниками и корзиной. После решения временные байты PR освобождаются. Байты принятого файла сохраняются в БД; исходники в S3 продолжают читаться через существующий адаптер.
- XLSX: меняются только указанные ячейки; сохраняются остальные части ZIP-пакета, стили и формулы. Сохранённые результаты формул удаляются, книга помечается для пересчёта в Excel. Правка неосновной ячейки объединённого диапазона отклоняется.
- XLS преобразуется в XLSX: переносятся значения, исходные формулы и оформление не восстанавливаются. Интерфейс предупреждает до отправки. Исходный XLS остаётся доступен.
- Книги, показанные частично, не редактируются (границы существующего просмотра: 50 листов, 2 000 строк, 100 столбцов, 20 000 заполненных ячеек на лист). Скрипты работают офлайн в ограниченных subprocess; формулы не вычисляются, внешние ресурсы не загружаются.
- Редакция DOCX использует существующий поддерживаемый набор текста, таблиц и форматирования. Сложная вёрстка и вложенные объекты остаются в исходнике.
- Для XLS и XML-пакетов добавлены `python3-openpyxl` и `python3-lxml` в Docker и CI.

Проверка: `npm test`; `node scripts/standalone-http-test.cjs --embedded --shares-only` для функции; полный `test:embedded` включает остальные сценарии и требует русского OCR. `folder-share-acceptance.cjs` использует реальную БД/Prisma/HTTP, проверяет ACL, область, отзыв/срок, атомарность, устаревшие PR, неизменность оригиналов и XLSX-пакеты. Браузерный сценарий фронта проверяет интерфейс со стабами API; он не заменяет серверные тесты.
