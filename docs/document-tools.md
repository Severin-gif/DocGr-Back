# Инструменты документов

Страница frontend: `/workspace/tools`, вход из рабочего пространства. Все операции выполняются на инфраструктуре DocGrid. Внешний API не требуется.

Поддерживаются объединение, извлечение/удаление/перестановка/поворот/разделение страниц, сжатие, DOCX → PDF, изображения → PDF, OCR с текстовым слоем, нумерация, PDF → DOCX, обезличивание, визуальное сравнение PDF, PDF → XLSX, текстовые водяные знаки, пароль AES-256 и комплект PDF/ZIP с описью.

## Установка

Развернуть backend перед frontend. Dockerfile устанавливает Python-зависимости из `scripts/document-tools-requirements.txt` в отдельное окружение, Ghostscript и существующие LibreOffice/Poppler/Tesseract. Миграция `20261012120000_document_tools` создаёт очередь; выполняется штатным startup migration runner.

В Docker дополнительные настройки не нужны. В запуске без Docker установить зависимости и указать `DOCGRID_TOOLS_PYTHON`, если Python находится вне PATH. Для защиты паролем используется ключ `DOCGRID_TOOLS_SECRET`, с резервом на существующий `DOCGRID_SERVICE_TOKEN`: пароль шифруется AES-GCM в очереди и удаляется после завершения. Ключ должен совпадать у всех реплик. `DOCGRID_TOOLS_ENABLED=false` останавливает приём и worker.

## API и сохранение

- `GET /api/docgrid/repositories/:projectId/tools/jobs` — последние 50 операций.
- `POST .../tools/jobs` — requestId UUID, tool, title, path, sources, options. Строгая валидация. Повтор requestId возвращает существующую операцию.
- `POST .../tools/inspect` — source и page, предпросмотр одной PDF-страницы.

Источник: материал с SHA-256 либо сохранённый документ с branchId и revision. Права чтения/записи проверяются при постановке, исполнении и сохранении. Результат добавляется через штатный uploadMaterial с квотой проекта, извлечением текста и индексацией; имена содержат идентификатор операции. Оригиналы сохраняются. Событие `tools.completed` хранит связи с источниками, параметры размера и результаты, без пароля или удаляемого текста.

Worker сериализован PostgreSQL advisory lock при получении задания, lease обновляется каждые 30 секунд. При аварии задание отмечается failed: автоматическое повторное сохранение не выполняется. В редком случае обрыва после сохранения файла он уже может находиться в папке результатов — проверьте её перед повтором.

Лимиты: до 30 исходников, 100 МБ суммарно, до 300 страниц PDF, 5 ожидающих операций на пользователя, одна тяжёлая операция на кластер. Дочерние процессы завершаются по таймауту 5 минут; предпросмотр — 30 секунд. Временные файлы удаляются, Python ограничен 2 ГБ адресного пространства и 150 МБ на файл.

## Ограничения качества

- PDF → DOCX восстанавливает текст и таблицы; сложная верстка и порядок блоков требуют ручной проверки.
- PDF → XLSX извлекает таблицы, при необходимости после OCR; значения записываются текстом, без выполнения формул из PDF. Проверять реквизиты и суммы.
- Обезличивание создаёт растровую копию 180 DPI с удалёнными областями, без исходного текстового слоя, вложений и форм. На сканах выбирать области вручную. Поиск строк действует только по существующему текстовому слою. Перед передачей проверить итоговый PDF.
- Сравнение выполняется по отрисовке соответствующих страниц; перестановка страниц может дать много различий. Это не юридическая оценка изменений.
- OCR сохраняет существующий текстовый слой и распознаёт страницы без него. Точность зависит от качества скана.
- Обработка пересоздаёт PDF и не сохраняет действительность исходных электронных подписей, интерактивные формы и аннотации. Оригинал доступен отдельно.

## Проверка

`npm run test:tools`: сборка, интеграция очереди с PGlite (права, валидация, квота, идемпотентность, шифрование, восстановление после сбоя) и 16 тестов Python на искусственных документах. UI: `tests/document-tools-browser-smoke.cjs` в frontend, 14 операций и мобильная компоновка.
