# Общая структура DOCX

Профиль `docgrid-structure-v1` задаёт оформление структурных элементов. Шаблоны договоров, актов, приложений, исков и отзывов в него не входят: их содержание и обязательные разделы будут предоставлены отдельно.

| Элемент | Стиль |
| --- | --- |
| Страница | A4; поля слева 25 мм, остальные 20 мм |
| Основной текст | Times New Roman 12 пт; первая строка 1,25 см; интервал 1,15; после абзаца 6 пт |
| Заголовок 1 | 16 пт, жирный, по центру |
| Заголовок 2 | 13 пт, жирный, слева |
| Заголовки 3–6 | 12 пт, жирный, слева |
| Пункт / подпункт | Висячий отступ; последовательные уровни 1,25 / 2,5 см |
| Примечание | Курсив |
| Адресный блок | Справа, без красной строки |
| Подпись | Слева, без красной строки |
| Таблица | Без красной строки, компактные интервалы |

Заголовки сохраняют уровень и связь со следующим абзацем. Жирный, курсив и подчёркивание сохраняются из исходного текста; система не определяет «важное» автоматически. Явное оформление исходного документа может переопределять базовый стиль. Текстовые номера пунктов сохраняются буквально; вложенные списки используют нумерацию Word. Автоматическое исправление ссылок и перенумерация обычных абзацев не выполняются.

Генерация и ручное сохранение используют один renderer. Внутренняя безопасная текстовая проекция нужна для сравнения, проверки и существующего интерфейса правок; рабочая редакция содержит реальный DOCX. Нового редактора или отдельных средств редактирования не добавлено. Преобразование безопасной проекции не гарантирует восстановление произвольных сложных объектов импортированного Word; оригинальные загруженные файлы сохраняются отдельно.

## Хранение и версии

Миграция `20261008174500_document_docx_structure` добавляет DOCX, SHA-256 и версию профиля в снимки веток и коммиты. Создание, сохранение, принятие PR и принятие правок по общей ссылке сохраняют текст и файл в одной транзакции. Ветка копирует исходные байты. Повторное скачивание возвращает сохранённый файл; пакет документов фиксирует те же байты. PDF является производным от DOCX.

Старые редакции преобразуются при первом авторизованном скачивании без изменения текста или номера редакции. Публичное чтение старых документов использует преобразование без записи. Экспорт несохранённого черновика требует права записи, возвращает DOCX и не создаёт редакцию.

Порядок внедрения: применить миграцию и обновить backend, затем frontend. До появления метаданных DOCX frontend поддерживает прежний просмотр.

Проверки: unit-тесты Word XML, HTTP-проверка сохранения/ветвления/PR/совместимости/ACL, проверка неизменного DOCX внутри пакета; браузерная проверка реального файла и ручного сохранения находится в парном frontend PR.
