# Обсуждение, сортировка и комплекты

Doc-Back хранит личные обсуждения автора внутри проекта. Оригиналы и созданные результаты находятся в общей файловой структуре проекта. Legal Core не участвует.

## Подключение

1. В AI-Orchestra включить существующий `DOCGRID_ENABLED=true`, настроить `DOCGRID_MODEL` (либо существующий резервный CODEX_DOC_MODEL/OPENROUTER_MODEL) и OpenRouter API key. Новая модель не обязательна.
2. В Doc-Back настроить `DOCGRID_ORCHESTRA_URL` (корень сервиса AI-Orchestra) и существующий `DOCGRID_SERVICE_TOKEN`. Токен должен совпадать с AI-Orchestra; браузеру он не передаётся.
3. Применить миграцию `20260928180000_docgrid_discussions` обычным стартом Doc-Back.
4. В «Доступе» создать доступ LLM: «Чтение» для Советника, «Подготовка изменений» для сортировки и комплектов. Новые папки и комплекты требуют доступа ко всему проекту; выбор контекста в композере дополнительно ограничивает передаваемые модели материалы.
5. Во вкладке «Обсуждение» выбрать доступ и создать обсуждение. Внешний коннектор продолжает работать через MCP в своём приложении; предложения обоих способов исполнения используют один журнал и согласование.

Срок, отзыв, текущая ACL и лимит операций проверяются тем же AstraService, что у внешних исполнителей. Встроенный вызов по автору и grantId не создаёт привилегированный JWT/агентский токен. Модель не получает ключи DocGrid. Снимки и чтение расходуют лимит операций; стоимость модели учитывает провайдер отдельно. `DOCGRID_REQUIRE_ZDR` сохранён.

## Границы первой версии

- Советник отвечает и классифицирует, но API не разрешает ему создать предложение изменений. Помощник и Ассистент подготавливают предложения; автоматического согласования нет. Ассистент пока выполняет шаги по сообщениям пользователя, без фонового автономного цикла.
- До 20 источников по 5 000 знаков на запрос, точный поиск фразы в извлечённом тексте и явная следующая порция. Это не семантический поиск, не весь текст большого документа и не обещание полного анализа проекта. Охват и статусы извлечения показаны в ответе.
- История последних четырёх завершённых запросов, до 200 сообщений в обсуждении. После аварийного прерывания незавершённый запрос через 10 минут становится ошибкой при обновлении истории. Повтор с тем же ключом не запускает новый оплачиваемый запрос.
- Мини-заключения сохраняют категорию, назначение, причину, уверенность и проверяемые дословные цитаты. В предложение переносов включаются только выводы высокой уверенности с цитатами. Остальные остаются рекомендациями для уточнения.
- Комплект сохраняется одной транзакцией: папка, перемещение выбранных приложений, до восьми черновиков. Устаревшее дерево отклоняется. Исходные байты не перезаписываются. Результаты доступны в «Файлах», просмотре версий и существующем экспорте.
- Платёжное поручение — черновик реквизитов, не банковский файл. Значения принимаются только при наличии дословной цитаты; остальные поля остаются пустыми. Нет проверки актуальности реквизитов/госпошлины через СПС, расчёта пошлины по актуальной редакции закона, отправки и оплаты. Перед использованием нужна проверка. Для подключения СПС потребуется отдельный проверяемый источник.
- Существующие grants не получают новое право `docgrid_propose_package` автоматически. Для комплектов выдать новый доступ с этим правом.

## Проверка и развёртывание

Порядок: AI-Orchestra (новый защищённый `/internal/docgrid/discussion`) → Doc-Back → frontend. Это три отдельных PR. Public `/ready` проверяет БД/режим хранения, но не доказывает работоспособность модели.

`npm test` проверяет контракт и существующие доменные сценарии. `npm run test:embedded` / CI PostgreSQL выполняют HTTP-проверку с тестовым ответом модели: ACL, повтор запросов, сортировка до/после согласования, режим Советника, недоступные источники, отклонение устаревшего комплекта без частичных записей, комплект + приложения + незаполненные реквизиты, отзыв grant и неверные цитаты. Реальный платный провайдер в тестах не вызывается.


## Встроенный чат и лимиты (29.09.2026)

Новый чат создаётся с `{title}`: отдельный токен или ручной grant больше не нужен.
Doc-Back создаёт внутренний grant с недоступным клиенту credential. Это тот же
журнал операций, снимки источников и механизм согласования, что у MCP.
Текущие права пользователя проверяются на каждом действии. Читатель может
создать снимок для чтения, но не предложить изменение; применение предложений
по-прежнему доступно владельцу. Старый `{title,grantId}` совместим.
Grant действует 30 дней / 10 000 операций; после истечения нужен новый чат.
Отзыв доступа или выключение встроенной LLM блокирует последующие действия,
включая применение ранее подготовленного предложения.

- `GET .../discussions/config`: доступные модели, состояние подключения, права,
  дневной лимит и остаток.
- `PUT .../discussions/settings {enabled:boolean}`: только владелец; настройка
  сохраняется в DocGrid и журналируется. По умолчанию `true`.
- `POST .../turns` принимает `model`: логический ID из серверного списка Orchestra.
- `DOCGRID_AI_DAILY_REQUEST_LIMIT`: 30 по умолчанию, допустимо 1–500.
  Счётчик в PostgreSQL общий для пользователя во всех проектах, сброс 00:00 UTC.
  Зарезервированная попытка учитывается даже при ошибке; повтор одного requestKey
  не расходует лимит. Атомарный UPSERT не допускает превышения при параллельных запросах.

## Текст исходных материалов

Поддерживаются текстовые PDF (до 200 страниц), UTF-8 TXT/MD, DOCX, DOC, XLSX,
XLS и ODT. Офисные файлы обрабатываются без запуска макросов и сетевых ссылок;
DOC — antiword, XLS — xlrd, XML-форматы — Python stdlib. Предел файла 32 МБ,
распаковки ZIP 32 МБ / 2000 записей, текста 200 000 символов; отдельный процесс
ограничен CPU, памятью, временем и выводом. XLSX использует сохранённые значения,
не пересчитывает формулы; отсутствие сохранённого результата отмечается PARTIAL.
OCR изображений и сканов в этой версии отсутствует.

- `GET .../materials/:id/text`: доступный текст, статус и причина; права чтения.
- `POST .../materials/:id/extract`: повторить обработку сохранённого оригинала;
  нужны права записи, повторная проверка ACL и SHA перед сохранением результата.
  Исходные байты/S3-ключ/SHA не меняются. Ошибка или занятый обработчик не стирают
  ранее доступный текст. Существующие снимки обсуждений остаются историческими.
- В списке файлов добавлено `extractionReason`; для старых строк может быть null.
  `READY` означает доступный текст, а не завершённый анализ ИИ.

## Обновление

1. Развернуть AI-Orchestra с `discussionModels` в `/internal/docgrid/config`.
2. Развернуть Doc-Back: новая миграция добавляет настройки, квоту, признак
   внутреннего grant и причину извлечения. Startup выполняет `prisma migrate deploy`.
   Нужна сборка нового Docker image с Python/xlrd/antiword; переменные базы и S3 не меняются.
3. Развернуть DocGr-fr. Для ранее загруженных файлов нажать «Извлечь недостающий текст».
   Обработка последовательная, её можно остановить; при закрытии страницы она прекращается.

Обработка реального проекта и проверка платного провайдера не выполняются CI:
тесты используют синтетические файлы/учётные записи и stub модели.
